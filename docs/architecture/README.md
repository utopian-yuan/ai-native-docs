# 架构、契约与长期决定

新成员先从[系统概览](system-overview.md)找到当前版本的入口、模块和数据归属。要改一段调用链时，找提供方、消费方和对应契约，再判断是否需要形成长期技术决定。

| 变化 | 维护人和写入位置 |
| --- | --- |
| 运行中的系统边界、依赖或状态归属改变 | 模块负责人更新[系统概览](system-overview.md)，链接能核实的版本 |
| 多模块要共同实现一个新方案 | 设计者在[技术方案](technical-design.md)写兼容、迁移、回退和待决问题 |
| 接口或事件字段变化 | 提供方更新[契约](contracts/README.md)，使用方验证历史输入和异常 |
| 长期技术选择被采用或替代 | 决策人维护 [ADR](decisions/README.md)，保留前版的约束和理由 |
| 设计图或可编辑源文件换版 | 作者更新[资产索引](assets/README.md)和引用它的正文 |

资料出现分歧时按[规范归属](authority.md)定位负责决定的人和维护源。
