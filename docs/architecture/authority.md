# 规范归属

| 要回答的问题 | 维护来源 |
| --- | --- |
| 用户应该得到什么能力 | 所属项目的已确认需求，及[功能工作项](../features/README.md)中接受的范围和 AC |
| 当前版本实际怎样运行 | 该版本的源码、接口定义、迁移、运行配置与证据，导航见 [系统概览](system-overview.md) |
| API、事件或 Agent 工具由谁维护 | [契约索引](contracts/README.md) 指定的原文、版本和责任人 |
| 哪些技术决定已经采用 | 已接受的 [ADR](decisions/README.md)，保留草案和替代轨迹 |
| 何时做、谁先做 | [路线图](../plan/roadmap.md) 管跨任务顺序，工作项 tasks.md 管实际执行 |
| 工作完成或验收了吗 | 工作项 change.md、evidence.md 和具名的验收决定 |
| 可否执行这次有授权要求的动作 | 当事人的原始决定，必要时索引到 [授权](../approvals/README.md) |
| 哪版在哪里运行、怎样恢复 | [发布记录](../releases/README.md) 与对应环境实测 |
| 这版谁交付了什么 | [CHANGELOG](../changes/CHANGELOG.md) 指向工作项、证据和版本 |
| 决定的来源与旧版本在哪里 | 工作项引用的原件或原始决定、对应提交、已替代的 ADR，以及各工作项分类的 archive |

规格与现状冲突时，写明来源和版本，指认受影响的需求、调用方和验收结果，交相关负责人决定。决定采用新行为后更新规格及相关契约。修复实现偏差时保留原验收条件与首次失败证据。
