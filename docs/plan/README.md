# 版本计划与跨团队分工

一个目标跨越多个工作项或需要分批交付时，由版本负责人维护计划。开工前写清目标、基线、纳入的工作项、里程碑、先后依赖、负责人和进入下一阶段的可观察条件。里程碑改变时注明决定日期、原因和下游影响。

- [路线图格式](roadmap.md) 用于跨版本或跨阶段安排。
- [分工和交接格式](ownership-and-handoff.md) 用于明确上游交什么、下游如何独立验证。
- [工单看板 0.4 候选版计划](PLAN-20260511-example-ticket-inbox.md) 是已填好的教学例子。从 M2 可以找到阻塞版本的 BUG、修复评审和最终进入测试环境的版本。

计划里的工作项使用相对链接，执行过程记录在四件套，发布事实由[发布记录](../releases/README.md)维护。
