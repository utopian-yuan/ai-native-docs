# 当前目录与协作约定的来源

团队采用下列 11 个一级目录。日常决策按 [文档中心](../README.md) 和 [规范归属](../architecture/authority.md) 找到负责维护的地方。

| 团队需要解决的问题 | 采用的做法 | 当前入口 |
| --- | --- | --- |
| 不同人员和 AI 接续工作 | 沿用 EDTQ 的任务主状态、具名负责、接受与最终验收、按交付署名 | [四件套](../_templates/README.md) · [变更日志](../changes/README.md) |
| 写出可实施、可检验的工作项 | 参考 jingshen-aireview 的影响面、风险、设计取舍与回滚、准备到收尾的任务、评审与覆盖记录 | [模板填写入口](../_templates/change/README.md) |
| 区分工作目的及关闭原因 | 沿用功能、缺陷、工程任务和各自的归档，并保留历史 ID | [功能](../features/README.md) · [缺陷](../bugs/README.md) · [任务](../tasks/README.md) |
| 将长期方案与一次开发关联 | 用架构、契约和 ADR 定长期约定，用计划排依赖，用指南保存可复做步骤 | [架构](../architecture/README.md) · [计划](../plan/README.md) · [指南](README.md) |
| 区分许可、审阅意见和实际发布 | 从 grant-pilot 等团队实践提取具名记录，按动作和版本追到证据 | [授权](../approvals/README.md) · [评审](../reviews/README.md) · [发布](../releases/README.md) |

具体业务需求或原始资料沿用接入项目已有的位置，由工作项链接原文。
