# 接入和迁移现有文档

## 空项目

1. 在目标项目根目录运行根 README 给出的安装命令。
2. 从 [文档中心](../README.md) 进入产品简报、MVP 范围、系统概览和路线图，填上本项目已知事实及待决定项。
3. 从 [四件套](../_templates/README.md) 复制第一个工作项，关联验收条件、实际实现和证据。一次可交付改版结束后更新 [CHANGELOG](../changes/CHANGELOG.md)。

## 已有项目

1. 先确认当前分支及未提交改动。安装脚本逐一补齐缺少的 Markdown 和 JSON，保留同名文件。检查演进中的 README、AGENTS.md 与 CLAUDE.md，将新入口合入当前做法。
2. 用 [规范归属](../architecture/authority.md) 盘点已有文档。可在新目录索引中链接原维护位置，或按团队决定搬迁一次，同时更新旧引用。优先对齐需求、契约、工作项和交付记录。
3. 保留已有 ID、批准人、证据日期和历史署名。移动工作项时同时更新 CHANGELOG、发布和验收引用。已有根 CHANGELOG 会保留，文档中心入口指到原日志。团队决定迁到 docs/changes 时，需要重算相对链接并把根文件改成导航。
4. 请一名没参与迁移的成员从产品需求追到任务、证据和交付版本，再从 CHANGELOG 按账号反向追到验收。校阅新增目录、引用和 Git 差异。

模板库自身的开发工作项、教学示例和真实交付日志保留在模板库，本项目的业务记录由接入团队填写。
