# 功能工作项

当用户将获得一项新能力，或团队有意改变已有操作结果时，在这里建 FEAT。先确定服务哪个角色、入口在哪里、原流程和新流程分别怎样，再写能从用户端观察到的验收条件。将接口方、页面方和验收人的分工落到同一套文档。

| 现在要做什么 | 从哪里进入 |
| --- | --- |
| 了解一项功能如何接受、分工和待签收 | [「我的待办」功能案例](FEAT-20260511-example-my-open/change.md) |
| 查看实施和联调交接 | [该案例的任务行](FEAT-20260511-example-my-open/tasks.md) |
| 新建或继续已有功能 | 先按目标查当前目录及[归档](archive/README.md)，找到同目标沿用原 ID，新目标从[模板](../_templates/README.md)复制 |

一次交付后在 CHANGELOG 写明实际贡献。验收决定由 change.md 引用。需要收存时将整套移到本类型的 archive。
