# 目录与接入方案

- 取两边一级目录并集。产品、契约、ADR、数据、素材、AI 规格与历史都保留各自维护位置。
- 业务、版本或日期命名的重复实例泛化为目录样板。参考项目特有的行业资料、原型角色和部署批次对应到可复用子目录。[当版逐项对照](https://github.com/utopian-yuan/ai-native-docs/blob/3e75bf4a2764bd40222fe65d7438def87048ee78/docs/guides/source-directory-map.md)
- CHANGELOG 迁至两个参考项目共用的 docs/changes 位置。原根文件保留入口。接入已有项目时尊重已存在的变更日志。
- 安装补齐 docs 的 Markdown 与 JSON 以及根指令，模板仓库真实工作记录和教学样本随各自仓库维护。

## 目录筛选后的设计

四件套沿用可读 JSON 元数据，扩充风险、日期和关联范围。六套样例放在各自分类及归档目录，统一使用四单样本和同一组候选版本。计划、评审和发布按版本关联。安装从保留的目录复制样例，新项目在 docs/changes 中开始自己的交付记录。
