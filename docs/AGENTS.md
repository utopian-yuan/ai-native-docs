# docs 文档维护约定

先读[根规则](../AGENTS.md)、[文档中心](README.md)与[规范归属](architecture/authority.md)。按本次任务读取相关入口及其维护源。

- 写之前先确定要改的事实归哪个目录、哪一份原文。需求编号、契约版本、工作项 ID 和证据锚点应能逐级追溯。一个事实只维护一处。
- 产品文档区分已确认范围、草稿和待决内容。架构区分当前行为与拟议方案。发现两处冲突时，在对应四件套或 ADR 记录冲突、影响和待决人，引用已经作出的决定。
- 工作项主状态维护在 change.md。阶段结论、失败和未验证项写在 evidence.md。评审、授权、运行报告和发布分别记录其可证明的范围。
- 原件、原型、证据附件和归档材料保留来源、版本、日期和适用范围。优先使用相对链接。涉及移动时，核对原引用、新入口、必要的兼容链接以及相关 manifest。
- 新增目录或更换长期入口时更新索引。阶段交付时按[变更日志规则](changes/README.md)留痕。核对改动范围、引用和各项用语，并运行 `git diff --check`。
